# Планировщик задач (go-final)

Дипломный проект курса по Go: веб-сервер планировщика задач, аналог TODO-листа.

Сервер хранит задачи в базе данных (SQLite по умолчанию или PostgreSQL)
и предоставляет REST API, с которым работает готовый фронтенд из директории `web`. У каждой задачи есть дата, заголовок,
комментарий и правило повторения. Обычная задача при выполнении удаляется,
периодическая переносится на следующую дату по правилу.

## Структура проекта

```
main.go            точка входа: открывает базу и запускает сервер
cmd/seed           утилита заполнения планировщика демонстрационными задачами
pkg/server         запуск HTTP-сервера, раздача фронтенда, чтение TODO_PORT
pkg/api            обработчики API, функция NextDate, аутентификация
pkg/db             работа с базой: схема, запросы к таблице scheduler, SQLite и PostgreSQL
web                файлы фронтенда (html, css, js)
tests              тесты API, выдаются вместе с заданием
Dockerfile         сборка докер-образа
docker-compose.yml запуск приложения вместе с PostgreSQL
```

## API

| Метод  | Путь                     | Назначение                                    |
|--------|--------------------------|-----------------------------------------------|
| GET    | `/api/nextdate`          | следующая дата по правилу повторения          |
| POST   | `/api/task`              | добавить задачу                               |
| GET    | `/api/task?id=`          | получить задачу                               |
| PUT    | `/api/task`              | изменить задачу                               |
| DELETE | `/api/task?id=`          | удалить задачу                                |
| POST   | `/api/task/done?id=`     | отметить задачу выполненной                   |
| GET    | `/api/tasks[?search=]`   | список ближайших задач, поиск                 |
| POST   | `/api/signin`            | вход по паролю, выдаёт JWT-токен              |

Ответы в формате JSON. При ошибке возвращается объект с полем `error`.

## Выполненные задания со звёздочкой

- Порт сервера задаётся переменной окружения `TODO_PORT`.
- Путь к файлу базы данных задаётся переменной окружения `TODO_DBFILE`.
- Правила повторения `w` (дни недели) и `m` (дни месяца) в дополнение к `d` и `y`.
- Поиск задач в `/api/tasks?search=`: по подстроке в заголовке и комментарии
  или по дате в формате `02.01.2006`.
- Аутентификация по паролю из `TODO_PASSWORD` с JWT-токеном в куке `token`.
- Докер-образ.
- Сверх задания: поддержка PostgreSQL и запуск через Docker Compose
  с базой в отдельном контейнере и постоянным хранением данных.

## Запуск локально

Требуется Go 1.24 или новее.

```bash
go run main.go
```

Сервер слушает порт 7540, в браузере открывайте http://localhost:7540/.
При первом запуске в текущей директории создаётся файл `scheduler.db`.

Переменные окружения:

| Переменная      | Назначение                                   | По умолчанию     |
|-----------------|----------------------------------------------|------------------|
| `TODO_PORT`     | порт веб-сервера                             | `7540`           |
| `TODO_DBFILE`   | путь к файлу базы данных SQLite              | `scheduler.db`   |
| `TODO_POSTGRES_DSN` | строка подключения к PostgreSQL; если задана, SQLite не используется | пусто |
| `TODO_PASSWORD` | пароль для входа; пустой — вход без пароля   | пусто            |

Переменные можно задать в файле `.env` в корне проекта, сервер читает его
при старте. Скопируйте `.env.example` в `.env` и измените значения:

```bash
cp .env.example .env
go run main.go
```

Файл `.env` исключён из git и из докер-образа. Переменные, заданные
в окружении явно, имеют приоритет над значениями из файла:

```bash
TODO_PORT=8080 TODO_DBFILE=/tmp/todo.db TODO_PASSWORD=12345 go run main.go
```

Если задан `TODO_PASSWORD`, при открытии главной страницы фронтенд перенаправит
на `/login.html`. После ввода пароля сервер выдаёт JWT-токен, который фронтенд
сохраняет в куке `token` на 8 часов. Полезная нагрузка токена содержит SHA-256
от пароля, поэтому после смены пароля старые токены перестают действовать.

## Запуск тестов

Тесты из директории `tests` обращаются к работающему серверу, поэтому сначала
запустите его в отдельном терминале, затем:

```bash
go test ./tests
```

Параметры в `tests/settings.go`:

| Переменная     | Значение в проекте | Что означает                                          |
|----------------|--------------------|-------------------------------------------------------|
| `Port`         | `7540`             | порт сервера; переопределяется `TODO_PORT`            |
| `DBFile`       | `../scheduler.db`  | путь к базе; переопределяется `TODO_DBFILE`           |
| `FullNextDate` | `true`             | проверять правила `w` и `m`                           |
| `Search`       | `true`             | проверять поиск в `/api/tasks`                        |
| `Token`        | пусто              | JWT-токен, если сервер запущен с `TODO_PASSWORD`      |

Если сервер запущен с паролем, получите токен и подставьте его в `Token`:

```bash
curl -X POST -d '{"password":"12345"}' http://localhost:7540/api/signin
```

Тест `TestTasks` удаляет все задачи из таблицы перед проверкой.

Юнит-тесты пакетов, которым сервер не нужен:

```bash
go test ./pkg/...
```

## Хранилище: SQLite или PostgreSQL

По умолчанию сервер использует файл SQLite, этого требует задание и на это
рассчитаны тесты из директории `tests`. Если задана переменная
`TODO_POSTGRES_DSN`, сервер подключается к PostgreSQL и при старте создаёт
таблицу `scheduler`, если её ещё нет. Схема и API одинаковы для обоих хранилищ.

Формат строки подключения:

```
postgres://<пользователь>:<пароль>@<хост>:<порт>/<база>?sslmode=disable
```

Пример: поднять только PostgreSQL из Docker Compose (порт 5432 проброшен
на localhost) и запустить сервер локально против него:

```bash
docker compose up -d db
TODO_POSTGRES_DSN=postgres://todo:secret@localhost:5432/todo?sslmode=disable go run main.go
```

Ту же строку можно записать в `.env` в переменную `TODO_POSTGRES_DSN`.

## Docker Compose: приложение и PostgreSQL

Файл `docker-compose.yml` поднимает два контейнера: `db` с PostgreSQL 17
и `app` с планировщиком. Приложение ждёт готовности базы по healthcheck
и подключается к ней по внутренней сети Compose. Данные PostgreSQL лежат
в именованном томе `pgdata` на диске хоста и сохраняются при остановке
и пересоздании контейнеров.

Пароли и имена читаются из `.env`:

```bash
cp .env.example .env     # задайте POSTGRES_PASSWORD и, если нужно, TODO_PASSWORD
docker compose up -d --build
```

Планировщик доступен по адресу http://localhost:7540/ (порт меняется
переменной `TODO_PORT` в `.env`). Переменные из `.env`, которые использует Compose:

| Переменная          | Назначение                                      |
|---------------------|-------------------------------------------------|
| `POSTGRES_USER`     | пользователь PostgreSQL                         |
| `POSTGRES_PASSWORD` | пароль PostgreSQL, обязателен                   |
| `POSTGRES_DB`       | имя базы                                        |
| `TODO_PORT`         | порт на хосте                                   |
| `TODO_PASSWORD`     | пароль планировщика, пустой — без пароля        |

Заполнить список демонстрационными задачами можно сервисом `seed`,
см. раздел «Заполнение TODO-листа демонстрационными задачами».

Полезные команды:

```bash
docker compose logs -f app        # логи приложения
docker compose down               # остановить, данные в томе сохраняются
docker compose down -v            # остановить и удалить том с данными
docker compose exec db psql -U todo -d todo -c 'SELECT * FROM scheduler'
```

Тесты из `tests` против Compose не запускаются: они читают файл SQLite напрямую.
Для проверки PostgreSQL-режима используйте браузер или запросы к API.

## Заполнение TODO-листа демонстрационными задачами

Чтобы не добавлять задачи вручную, есть утилита `cmd/seed`. Она обращается
к API работающего сервера и добавляет 12 задач с разными датами и правилами
повторения. Утилита работает через HTTP, поэтому хранилище сервера не важно:
подходит и для SQLite, и для PostgreSQL. Если на сервере задан пароль,
утилита сама выполняет вход через `/api/signin`.

По умолчанию задачи добавляются только в пустой список. Флаг `-force`
добавляет их в любом случае.

Заполнить планировщик в Compose-стеке:

```bash
docker compose up -d --build
docker compose --profile seed run --rm seed
```

Добавить задачи повторно, даже если список не пустой:

```bash
docker compose --profile seed run --rm seed /app/seed -force
```

Заполнить локально запущенный сервер:

```bash
go run ./cmd/seed                              # localhost:7540
go run ./cmd/seed -password 12345              # если на сервере задан пароль
go run ./cmd/seed -addr http://localhost:8080  # другой адрес
go run ./cmd/seed -force
```

Флаги утилиты:

| Флаг        | Переменная окружения | Назначение                                   | По умолчанию            |
|-------------|----------------------|----------------------------------------------|-------------------------|
| `-addr`     | `TODO_ADDR`          | адрес сервера                                | `http://localhost:7540` |
| `-password` | `TODO_PASSWORD`      | пароль планировщика                          | пусто                   |
| `-force`    |                      | добавить, даже если список не пустой         | выключен                |
| `-wait`     |                      | сколько ждать, пока сервер станет доступен   | `30s`                   |

При запуске из корня проекта переменные подхватываются из `.env`,
поэтому пароль обычно указывать не нужно. В Compose сервис `seed`
получает адрес `http://app:7540` и пароль из `.env` автоматически.

## Docker: один контейнер с SQLite

Сборка образа из корня проекта:

```bash
docker build -t go-final .
```

Запуск контейнера с базой данных на хосте. Директория `./data` на хосте
монтируется в `/data` контейнера, файл базы появится в `./data/scheduler.db`:

```bash
mkdir -p data
docker run -d --name go-final -p 7540:7540 -v "$(pwd)/data:/data" go-final
```

Переменные можно передать из файла: `docker run --env-file .env ...`.
С паролем и другим портом на хосте:

```bash
docker run -d --name go-final -p 8080:7540 -v "$(pwd)/data:/data" \
  -e TODO_PASSWORD=12345 go-final
```

После запуска планировщик доступен в браузере по адресу http://localhost:7540/
(или по порту, указанному в `-p`).

Тесты запускайте против сервера, запущенного локально через `go run`, а не
против контейнера. Тест `TestTasks` меняет файл базы напрямую, а Docker на
macOS и Windows не гарантирует согласованность файла SQLite, открытого
одновременно на хосте и внутри контейнера.

Остановка и удаление контейнера:

```bash
docker stop go-final && docker rm go-final
```
